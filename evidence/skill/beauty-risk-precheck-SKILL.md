# 美妆顾客问询风险预检

## 目标与边界

本 Skill 只回答一件事：顾客问询是否必须在**知识检索前**直接转人工。

- 仅供客服、导购在内部使用；不向消费者发送内容。
- `DIRECT_HUMAN_HANDOFF` 不是医疗、质量或售后结论，而是停止自动链路的信号。
- 只识别问询文本中可直接判断的三类风险：敏感人群/特殊使用条件、疑似不良反应、复杂客诉。
- 未触发时输出 `PROCEED_TO_RETRIEVAL`，仅代表可进入知识检索；仍须完成检索、检索后风险复核和人工审核。

## 输入

必填：`question`（顾客原话或客服整理后的咨询）。

## 决策规则

1. 问题出现敏感肤质、孕期、儿童、皮肤破损或正在用药 → `SENSITIVE_POPULATION`。
2. 问题出现红肿、刺痛、瘙痒、水疱、眼部不适、就医或不良反应 → `SUSPECTED_ADVERSE_REACTION`。
3. 问题出现投诉、赔偿、媒体或监管 → `COMPLEX_COMPLAINT`。
4. 命中多个规则时必须完整列出，不得只报第一条。

## 输出

输出结构包含：`next_step`、全部 `reasons`，以及仅在直接转人工时生成的 `handoff_package`。

人工确认包必须保留原问题、触发原因与待确认项。它不应包含诊断、赔偿金额、退换货批准或对客承诺。

## 不属于本 Skill 的工作

- 知识检索、引用文档或判断资料是否充分；这些发生在预检放行后的下一步。
- 检索后的规则冲突复核；这是系统流程中的后续判断，不重复调用本 Skill。
- 生成客服答复或向顾客发送内容。

## 运行与测试

在本目录运行：

```bash
python3 scripts/precheck.py --question "用了以后刺痛，要不要停用？"
python3 evals/run_evals.py
```

规则依据见 `references/risk-policy.md`，金标用例见 `evals/cases.json`。根目录的早期脚本仅作过程保留，不作为当前调用入口。
